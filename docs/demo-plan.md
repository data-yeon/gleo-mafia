## Context
- **요청:** 42dot 자율주행 영상(https://www.youtube.com/watch?v=1ZG63np_HoU)의 Pleos 차량 화면을 그대로 가져와, 주행 화면 속에서 게임이 끊김 없이 이어지는 데모를 Godot로 만든다.
  - 화면 구성: 왼쪽은 차량, 가운데와 오른쪽은 내비.
- **지금 상태:**
  - Python 퍼즐 공장(`prototype/`)이 있고, 검증된 퍼즐을 JSON 팩으로 내보낸다.
  - Godot 골격(`godot/`)은 어두운 자체 UI 위에 가상 경로를 그리는 수준이다.
- **사용자 결정 (2026-10-20):**
  - 데모는 맥/PC 전체화면으로 한다.
  - 지도는 실제 서울 경로 + OSM 데이터로 만든다.
  - 음성은 실시간 STT + LLM으로 하고, 실패하면 버튼과 템플릿으로 자동 전환한다.
  - 스도쿠 규칙에 매달리지 말고, **내비 UX 언어로 Dupery를 풀어낸다.**
- **목표:** "자율주행 중인 차 화면의 한 모드"처럼 보이는 3~4분 라이브 데모.

## 1. 영상에서 본 Pleos 자율주행 화면
- **전체:** 밝은 테마, 가로형 화면.
- **위쪽 상태바:** 속도, 아이콘, 시각.
- **왼쪽 약 30%, 자율주행 시각화:** 흰 배경, 회색 도로와 차선, 내 차(흰 3D), 주변 차(회색 3D), 파란 주행 경로 띠.
- **오른쪽 약 70%, 내비 지도:**
  - 밝은 회색 땅, 흰 도로, 초록 공원, 파란 강, 경로선, 내 위치 화살표.
  - 왼쪽 위: 회전 안내(TBT) 카드. 거리와 도로명.
  - 왼쪽 아래: 도착 정보 카드.
  - 오른쪽 가장자리: 세로 버튼과 목록 열.
- **아래쪽:** 앱 독(아이콘과 공조).
- **영상 고정 댓글 정보:** Pleos OS는 AAOS를 포크한 것이고, 자체 앱마켓(베타)이 있으며, Gleo AI(LLM)로 차량을 제어한다.

## 2. 핵심 설계: Dupery를 내비 언어로 다시 쓰기
게임 화면을 따로 만들지 않는다. **기존 내비 구성요소에 사건 정보를 얹는다.** 레이아웃은 바뀌지 않는다.

| Dupery | 내비 UX로 옮긴 것 |
|---|---|
| 격자 위의 문(주소) | **경로를 따라 지나갈 실제 장소 9곳.** 번호 = 지나가는 순서. 오른쪽 가장자리 목록이 TBT 목록처럼 "2.1km 앞 · 오른편 · ③ 강변역"으로 보여준다 |
| 문을 연다(조사) | 장소 핀이나 목록을 누르면 **POI 상세 카드**가 뜨고, [탐문] 버튼은 Gleo가 그곳 제보자에게 "전화"를 거는 것 |
| 조사 1회 = 2시간 | 탐문 1회 = 통화 약 2분. **남은 탐문 수는 ETA로 정해진다**("남은 시간에 4번 더 통화할 수 있어요") |
| 아침(24시) 전까지 | **도착 전까지.** 도착 5분 전에는 출동만 가능(기존 최종 단계) |
| 이웃, 열, 주소 합 같은 능력 | **경로 기준 관계:** 지나가는 순서상 앞뒤, 경로 왼편/오른편, 구간(③~⑥ 사이), 반경, 업종 |
| 시계탑 종, 이벤트 | **실제 주행 이벤트:** 길가 장소 통과(잠복), 터널(은폐), 신호 대기(보너스 통화) |
| 체포 | **출동:** 경찰차 아이콘이 지도 위를 달려가 도착하면 결과가 나온다. 왼쪽 주행 화면에서 경찰차가 내 차를 추월한다 |
| 평판 | 신뢰도(기존) |
| 수사 보드(핀, 실, 메모) | 장소 목록의 **태그(의심/무고)** + 지도 위 단서 오버레이 + Gleo "정리해줘" |
| 리드 3개 중 선택 | 목적지를 정하면 나오는 **경로 옵션 카드 3장**과 같은 모양의 **사건 제안 카드 3장** |
| 사건 사이 보상 | **도착 카드**("목적지에 도착했습니다") 안의 보상 선택 |
| 내레이터, 사회자 | Gleo(음성 바) |

## 3. 룰 v1 ("내비 Dupery") — 엔진 변경점
진실·거짓 구조(역할 4분류, 거짓 진술, 위장, 오염, 은폐, 말썽꾼, 잠복, 급습 = 출동, 신뢰도, 최종 단계)는 **그대로 둔다.**
바꾸는 것은 **공간 관계를 내비 언어로 바꾸는 것**과 **주행 이벤트를 규칙에 넣는 것**이다.

1. **보드:** 실제 경로 회랑(경로 양쪽 약 1.5km)에서 실제 POI 9곳을 고른다.
   - 각 장소 속성:
     - 지나가는 순서(1~9)
     - 경로 기준 **왼편/오른편**(진행 방향 기준)
     - 길가 여부(300m 이내)
     - 업종
   - 선정 기준:
     - 길가 2~3곳
     - 최소 간격 700m
     - 왼편/오른편 균형(4:5 또는 5:4)
     - 공공장소와 랜드마크 우선
2. **단서 유형 교체** (지도 표시는 내비 오버레이 문법을 따른다)
   | 역할 | 기존 | v1 | 대사 예 | 지도 표시 |
   |---|---|---|---|---|
   | 노점상 | 반경 | 반경(유지) | "여기서 1km 안에 1곳" | 주변 검색 반경 원 |
   | 택시기사 | 길가 | **구간** | "③에서 ⑥ 사이 지나는 길에 1곳" | 경로 구간 하이라이트 |
   | 드론 유튜버 | 지도 절반(북/남) | **편** | "경로 오른편엔 2곳" | 경로 기준 한쪽 음영 |
   | 동네 토박이 | 가까운 두 곳 | **앞뒤 이웃** | "내 바로 앞뒤로 지나가는 두 곳 중 1곳" | 목록과 경로에서 앞뒤 연결 |
   | 배달 라이더 | 업종 | 업종(유지) | "카페 쪽엔 없어요" | 업종 필터 칩 |
   | 경비원 | 보증/고발 | 유지 | "⑤는 깨끗해요" | 화살표 |
   | 순찰 경관 | 정체 확인 | 유지 + **보이스피싱 사업부에서는 사칭 가능** | "⑥ 사람, 신분 속여요" | 배지 |
   - 길가 개수 단서는 택시기사의 두 번째 형태로 남긴다("바로 지나가는 곳들 중 1곳").
3. **잠복:** 길가 장소에 다가가면 TBT 경고 카드("300m 앞 오른편 ② 강변역 · 잠복 가능")가 뜬다.
   - **지나치면 기회가 사라진다(새 규칙).** 지나가는 순서가 곧 시간 압박이 된다.
4. **탐문 수:** 난이도별 기본값 + ETA 보정(보고서 4절). 화면에는 "남은 통화 N회"로 표시한다.
5. **출동:** 출동 버튼을 누르면 경찰 아이콘이 이동하고 10~20초 뒤 결과가 나온다. 신뢰도 규칙은 기존과 같다.
6. **보스 오염:** 반경 1km를 "통신 음영 구역"으로 표현한다. 사건이 끝난 뒤 지도에 공개한다.
7. **보이스피싱 사업부(데모 사건):**
   - 사칭범(행동대원 변형)은 경관 행세를 할 수 있다.
   - 익명 제보 1개(직업 비공개)가 들어온다.
8. **검증 기준:** smart 봇이 잠복을 써서 보통 난이도에서 찍기 없이 75% 이상 풀 것. 사람 대상 테스트로 최종 확정한다.

## 4. 화면 흐름 (모두 Pleos 화면 위에서)
1. **주행:** 영상과 같은 화면. 상단 "3x Speed" 라벨, 경로 안내 중, 왼쪽 자율주행 시각화.
2. **제안:** Gleo 음성 바가 말한다. "도착까지 20분이에요. 사건 하나 맡아볼까요?"
   - 수락하면 지도가 경로 전체가 보이게 축소된다.
   - 9곳 핀이 내비 POI 마커 모양으로 떨어진다.
   - 오른쪽 열이 **사건 장소 목록**(지나가는 순서)으로 바뀐다.
   - TBT 카드 자리에 **브리핑 카드**, ETA 카드에 "남은 통화 · 신뢰도 · 남은 조직원"이 들어간다.
3. **탐문:**
   - 장소를 고르면 POI 카드가 뜬다(이름, 업종, "1.2km 앞 · 오른편", 버튼 [탐문][잠복][출동][태그]).
   - 대사는 음성 바와 자막으로 나온다.
   - 단서는 지도 오버레이와 목록 칩으로 남는다.
4. **잠복 찬스:** 길가 장소 접근 시 TBT 경고 카드가 뜨고, 지나치면 사라진다.
5. **터널, 신호 대기:** 실제 경로 데이터의 구간에서 은폐나 보너스 통화가 발생한다.
6. **최종 단계(도착 5분 전):** 지도가 붉게 물들고, 출동만 할 수 있다.
7. **도착:** 내비 도착 카드에 사건 결과, 정답 공개, 보상 카드 3장이 나온다.
8. **반전 연출(데모 하이라이트):** 경관이라던 제보자가 사칭범으로 드러난다.

## 5. 기술 구조

### 데이터 파이프라인 (Python, 오프라인)
- `prototype/tools/route_extract.py` (신규)
  - 출발지와 목적지 좌표를 받아 OSRM 공개 서버로 경로와 회전 안내 단계를 받는다.
  - Overpass(OSM)로 도로, 강, 공원, POI를 받는다.
  - 경로 원점 기준 미터 좌표로 바꿔 `godot/data/routes/<id>/map.json`(도로, 수계, 녹지), `route.json`(폴리라인, 회전 안내, 속도, 터널·정차 구간)을 만든다.
  - 지도 출처 표기 "© OpenStreetMap contributors"를 넣는다.
- `prototype/puzzle/board.py`: 실제 POI 목록에서 9곳을 고르는 `board_from_route()`를 추가한다. 기존 합성 보드는 테스트용으로 남긴다.
- `model.py`, `generator.py`, `solver.py`, `text.py`
  - 단서 SPAN, SIDE, NEIGHBOR를 추가한다. HALF와 NEAR는 v1에서 쓰지 않는다.
  - 사칭 규칙과 익명 제보를 추가한다.
  - 잠복 만료를 반영해 봇을 수정하고, 통계를 다시 낸다.
- `export_pack.py`: 스키마 v2를 만든다.
  - 장소에 `side`, `order`, `distanceFromRouteM`, `poiSource`를 넣는다.
  - 새 단서 필드를 넣는다.
  - 경로 id를 참조하게 한다.
  - `docs/puzzle-pack-schema.md`도 갱신한다.

### Godot (4.7, GDScript)
기존 파일은 다음처럼 재사용하거나 정리한다.
- `puzzle_case.gd`: 규칙을 확장한다(잠복 만료, 출동 지연, 익명 제보).
- `tests/test_puzzle_case.gd`: 테스트를 확장한다.
- 스크린샷 자동 실행 기능: `main.gd`의 `--autoplay` / `--screenshot`을 새 셸로 옮긴다.
- `gleo_voice.gd`: TTS 공급자 하나로 쪼갠다.
- `map_view.gd`: 오버레이 그리기 코드를 `case_overlay.gd`로 옮기고 정리한다.

| 폴더 / 파일 | 역할 |
|---|---|

| `scripts/shell/pleos_theme.gd` | 밝은 테마 색, 둥근 카드, 폰트(Pretendard, OFL) |

- **API 키:** 환경변수나 git에서 제외한 설정 파일에서 읽는다.
- **LLM:** 해커톤에서 Gleo API를 주면 그것을 쓰고, 없으면 Claude API(저지연 모델)를 쓴다.
- **TTS:** 캐릭터별로 다른 목소리가 필요하면 클라우드 TTS를 쓰고, 기본은 OS TTS다.

## 6. 단계별 진행 (우선순위)
| 단계 | 내용 | 우선 | 완료 기준 |
|---|---|---|---|
| A | 룰 v1 엔진 (단서 교체, 잠복 만료, 사칭, 실제 POI 보드), 통계 재실행 | Must | 단위 테스트 통과, 보통 난이도 찍기 없이 75% 이상 |
| B | 경로·지도 데이터 파이프라인 (데모 경로 1개 확정, OSM/OSRM 추출) | Must | Godot에서 실제 도로와 경로가 그려짐 |
| C | Pleos 셸 재현 (레이아웃, 테마, 상태바, 독, 카드 컴포넌트) | Must | 영상 프레임과 나란히 놓고 비교한 스크린샷 |
| D | 주행 시뮬레이션 + 내비 지도 + TBT/ETA + 자율주행 패널 (박스 차량 임시) | Must | 3배속 주행이 끊김 없이 재생됨 |
| E | 사건 모드 레이어 (전환, 장소 목록, POI 카드, 오버레이, 잠복 경고, 출동, 최종, 도착 결과) | Must | 데모 사건 한 판을 버튼만으로 끝까지 진행 |
| F | Gleo 음성 (누르고 말하기, 명령 해석, TTS, LLM 대사와 검증, 폴백) | Must | 네트워크를 끊어도 진행 가능 |
| G | Blender 3D 에셋 (내 차, 주변 차, 경찰차) | Should | 왼쪽 패널에 실제 모델 |
| H | 런 맛보기 (경로 옵션 모양의 사건 제안 카드, 도착 보상 카드) | Should | 데모 시작과 끝 연출 |
| I | 데모 연출·리허설 (발표자 단축키, 고정 시드, 백업 녹화) | Must | 4분 리허설 3회 무사고 |

- 병렬 진행 가능: B와 G는 A, C와 독립적이다. 승인 후 별도 세션으로 나눌 수 있다.
- 순서: A·B·G(병렬) → C → D → E → F → H → I

## 7. 검증
- **Python:**
  - `python3 -m unittest discover -s tests`
  - `python3 batch.py --n 200`: v1 단서와 잠복 만료 반영 통계
- **Godot 규칙:** `godot --headless --path godot --script res://tests/test_puzzle_case.gd`
  - 새 규칙(잠복 만료, 출동 지연, 사칭)을 테스트에 추가한다.

- **화면:**
  - `--autoplay` / `--screenshot`으로 단계마다(주행, 제안, 탐문, 잠복 경고, 최종, 도착) 스크린샷을 찍는다.

- **음성:** 마이크 → 명령 → 대사 → TTS 전체 왕복 지연(목표 3초 이내)을 측정한다. 네트워크를 끊었을 때 폴백 동작도 확인한다.
